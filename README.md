# HCM-Net

HCM-Net is a PyTorch Lightning project for hierarchical obstruction
classification from standard apical-view echocardiography cine loops. A
single video contains the apex, mid-ventricular, and outflow tract regions.
The model predicts regional obstruction states and a global patient-level
state jointly.

## Task definition

The regional source labels have the following meaning:

- `1`: resting obstruction
- `2`: latent obstruction
- `3`: no obstruction

Each outflow and middle prediction is hierarchical:

1. Coarse classification: obstruction versus no obstruction.
2. Conditional fine classification: resting versus latent, evaluated only for
   samples whose ground-truth coarse label is obstruction.

The apex branch is binary because the dataset contains no latent apex cases.
Since the v2 label revision, the apex branch predicts the **mid-apical
obstructive phenotype**, a distal phenotype nested within the midventricular
(MVO) spectrum: an examination counts as positive only when the apex is
obstructed *and* the middle segment is obstructed (isolated apical
hypertrophy without MVO is not included). The overall branch is defined by
LVOT (outflow) or MVO obstruction only (`overall = LVOTO ∨ MVO`), and
predicts both healthy/unhealthy and the derived `none`/`latent`/`resting`
three-class target (derived from the LVOT/middle labels).

## Model

The default model is designed for the limited cohort size:

- ImageNet-pretrained ResNet frame encoder adapted to one grayscale input
  channel, exposing both the layer3 map (stride 16) and the layer4 map
  (stride 32).
- A lightweight FPN-style fusion (`model.region_feature: fpn`) feeds the
  regional branches a higher-resolution feature map; set it to `layer3` or
  `layer4` to ablate the fusion.
- Two pooling orders (`model.pooling_order`): `temporal_first` collapses time
  at every spatial feature location before regional pooling (the original
  design); `spatial_first` (the default) pools each anatomical region per
  frame and then aggregates every region's frame-embedding sequence with its
  own temporal attention, so each branch keeps region-specific dynamics.
- Separate anatomy-guided spatial attention for apex, middle, and outflow
  regions.
- Global pooling for the overall heads.
- Class-balanced focal losses for all hierarchical nodes.
- Masked fine losses for obstructed outflow and middle samples.
- A differentiable regional-to-global consistency loss. The soft OR of the
  LVOT and midventricular obstruction probabilities is matched to the
  overall head (the mid-apical phenotype, nested in the MVO spectrum, is
  not an independent contributor).
- The same soft OR is reported as `overall_derived`: the deployed overall
  score is computed directly from the LVOT/midventricular heads, and
  checkpoint selection monitors `val/mean_coarse_auroc` (mean AUROC of the
  three regional coarse tasks plus `overall_derived`).
- `model.flat_heads: true` replaces the coarse+fine head pairs of the LVOT
  and midventricular branches with single flat three-class
  (none/latent/resting) heads for the no-hierarchy ablation; at evaluation
  time the flat probabilities are expanded back into the standard
  coarse/fine/cascade outputs so the metrics and prediction CSVs keep the
  same schema.

`model.attention_mode` in the configuration supports three ablations:

- `global`: every regional head uses the complete feature map.
- `hard`: fixed top, middle, and bottom thirds.
- `soft`: learnable content attention anchored by configurable vertical
  anatomical priors.

The default prior assumes apex near the top of the image, middle in the
center, and outflow near the bottom. Verify this convention on the exported
videos before training and adjust `model.prior_centers` if necessary.

## Data layout

The expected repository layout is:

```text
hcm-net/
├── hcmdata_raw/
│   ├── <image_id>.npz
│   └── ...
├── hcmdata/
│   ├── <image_id>.npy
│   ├── normalization_stats.json
│   └── ...
├── processed_labels.csv
├── configs/train.yaml
└── main.py
```

Raw samples are named `<image_id>.npz` and contain uint8 grayscale arrays in
`[T, H, W]` layout. The preprocessing script estimates the ultrasound sector
bounding box from a multi-frame max projection (peak-anchored row/column
spans, so detached ECG traces and text overlays are excluded) and writes
uncompressed `<image_id>.npy` arrays to `hcmdata/` together with
`crop_boxes.json` for audit. Training memory-maps these files and reads only
the selected frames. The channel dimension is added by the dataset loader.
`image_id` and `patient_id` are read as strings, so leading zeros are
preserved.

Create the cropped training arrays and recompute exact normalization
statistics with:

```bash
python preprocess_scripts/crop_videos.py
```

`processed_labels.csv` is generated by
[`preprocess_scripts/preprocess_labels.py`](preprocess_scripts/preprocess_labels.py)
from a raw physician label table (CLI: `--input/--output/--report
[--encoding]`; pass `--encoding` when the source CSV is not UTF-8). It
includes:

- `patient_id` for leakage-safe grouping of repeat examinations.
- Regional coarse labels and conditional fine labels (v2: `apex_coarse`
  follows the MVO-spectrum rule; the physician's original overall column is
  preserved as `overall_original`, while `overall`/`overall_fine` are
  derived from LVOT/middle only).
- The derived overall fine label.
- Image quality and substituted-view metadata.

[`example_labels.csv`](example_labels.csv) ships ten anonymized
examinations (synthetic IDs) that illustrate every label pattern: isolated
resting/latent LVOTO, isolated resting/latent MVO, the mid-apical
phenotype nested in the resting and latent MVO spectrum, combined
LVOTO + MVO, a fully negative examination, an isolated apical finding
that does *not* count as the mid-apical phenotype under the v2 rule, and a
repeat-examination pair sharing one `patient_id` with different labels.

All available samples are assigned to train or validation. There is no test
split in the current implementation. A five-fold iterative multilabel
stratification is performed at the patient level; all examinations from one
patient always remain in the same fold. To keep cross-round experiments
comparable when label definitions change, `data.fixed_fold_assignments`
can point at a frozen `fold_assignments.csv` (image_id/patient_id/fold)
that replaces the regenerated split after strict identity checks.

## Installation

Create an environment with a PyTorch build appropriate for the local CUDA
installation, then install the project dependencies:

```bash
pip install -r requirements.txt
```

The project pins `pytorch-lightning` to version 2.6.1. The first default run
downloads the torchvision ResNet-18 ImageNet weights if they are not already
cached. Its first convolution is converted to one input channel by summing
the pretrained RGB kernels.

## Training

Run one fold on one GPU:

```bash
python main.py --config configs/train.yaml --fold 0 --devices 1
```

Run one fold with Distributed Data Parallel on GPUs 0 and 1:

```bash
python main.py --config configs/train.yaml --fold 0 --devices 0,1
```

Resume from a checkpoint:

```bash
python main.py --config configs/train.yaml \
  --fold 0 \
  --devices 0,1 \
  --resume outputs/<experiment>/fold_0/version_0/checkpoints/last.ckpt
```

Train all five folds by launching `main.py` separately with `--fold` values
from 0 through 4. Important parameters such as clip length, image size,
batch size, precision, accumulation, backbone learning rate, loss weights,
and attention mode are defined in [`configs/train.yaml`](configs/train.yaml).

## Standalone fold validation

Validate a checkpoint only on its held-out fold and export one row per
validation examination:

```bash
python validate_fold.py \
  --config configs/train.yaml \
  --fold 0 \
  --checkpoint outputs/<experiment>/fold_0/version_0/checkpoints/<checkpoint>.ckpt
```

Use `--output path/to/predictions.csv` to override the default
`validation_predictions_fold_<fold>.csv` in the checkpoint run directory.
Validation intentionally uses one device so every examination is exported
exactly once. Use `--accelerator cpu` when a GPU is unavailable; otherwise the
accelerator comes from the training configuration.

The script checks the requested fold against the checkpoint directory and,
when available, checks the regenerated patient-level split against the run's
`fold_assignments.csv`. It writes:
- A prediction CSV containing the validation subset of `processed_labels.csv`
  with all original clinical metadata.
- `pred_<task>` and `confidence_<task>` for each model task.
- One `p_<task>_<class>` column per class, including the outflow and middle
  end-to-end cascade probabilities required for multiclass ROC analysis.
- Integer `target_<task>` columns. Conditional fine targets are empty for
  non-obstructed samples.
- A sibling `<prediction_stem>_metrics.json` containing the existing
  validation metric suite and checkpoint provenance.
- `calibration_fold_<fold>.json` with per-task temperatures and decision
  thresholds fitted on the held-out fold (Youden's J by default, `--no-temperature`
  and `--calibration-criterion f1` are available). The prediction CSV also
  carries `pred_<task>_calibrated` columns at those thresholds, and the
  metrics JSON reports them under `calibrated_in_sample`.

Run the command separately for folds 0 through 4, using the checkpoint trained
for the corresponding fold. Evaluation defaults to five temporal clips per
video (`--num-clips`, each covering `eval_window_ratio` of the loop) with
their logits averaged; pass `--num-clips 1` for a single deterministic
full-video pass.

## Independent external test

Evaluate one trained checkpoint on an independent external dataset:

```bash
python predict.py \
  --checkpoint outputs/<experiment>/fold_0/version_0/checkpoints/<checkpoint>.ckpt \
  --labels /path/to/external_labels.csv \
  --data-dir /path/to/external_npy_dir \
  --num-clips 5 \
  --calibration outputs/<experiment>/fold_0/version_0/calibration_fold_0.json
```

`--labels` and `--data-dir` are required; the external label CSV follows the
same schema as `example_labels.csv`. Use `--output` to choose the prediction
CSV location and `--accelerator cpu` when a GPU is unavailable.

Independent testing does not create or apply a fold split. Every row in the
external label CSV is evaluated exactly once. By default five temporal clips
are sampled per video (`--num-clips`, each covering `--clip-window-ratio` of
the loop) and their logits are averaged; `--num-clips 1` restores deterministic
full-video sampling. Input size and normalization are taken from the training
configuration rather than recomputed from the external cohort. Passing
`--calibration` applies the fold-fitted temperatures to the logits and adds
`pred_<task>_calibrated` columns at the fitted thresholds; thresholded metrics
are reported under `calibrated` in the metrics JSON. The script writes:

- `independent_test_external_predictions.csv`, retaining the original external
  labels and adding the same predictions, class probabilities, targets, and
  logic-disagreement flag as fold validation.
- `independent_test_external_predictions_metrics.json`, containing the complete
  metric suite and data/checkpoint provenance.

To compare the five cross-validation models independently, run `predict.py`
once for each fold checkpoint and give each run a distinct `--output` path.

## Outputs

Each run writes the following under `outputs/`:

- TensorBoard event logs and the complete hyperparameter configuration.
- `fold_assignments.csv` for reproducible patient-level split auditing.
- `validation_metrics.log` with the metrics printed after every validation epoch.
- The eight checkpoints with the highest `trainer.monitor` value (default
  `val/mean_coarse_auroc`, the mean AUROC of the three regional coarse tasks
  plus the soft-OR `overall_derived`). When `trainer.ema_decay` is positive,
  checkpoints store the EMA weights.
- `last.ckpt` for resuming an interrupted run.

Start TensorBoard with:

```bash
tensorboard --logdir outputs
```

Validation reports AUROC, AUPRC, accuracy, F1, sensitivity, specificity, PPV,
NPV, Brier score, and expected calibration error. Outflow and middle also
report end-to-end cascaded three-class metrics. Alongside the learned
`overall_coarse` head, the soft-OR combination of the LVOT and
midventricular coarse probabilities is reported as `overall_derived`. The
model logs the hard
regional/global logic disagreement rate as an additional quality-control
signal.

## Practical notes

- Cropped NPY arrays are memory-mapped so temporal sampling does not load the
  complete cine loop. Increase `num_workers` only after checking host memory
  and storage throughput.
- Grayscale normalization uses `mean=0.136364` and `std=0.219420`, computed
  exactly from all 65,203,941,060 cropped pixels across 1,067 samples after
  scaling uint8 values to `[0, 1]`.
- Spatial augmentation deliberately excludes horizontal and vertical flips
  to preserve anatomical orientation. Rotation, brightness, contrast, and
  temporal-window jitter are shared consistently across all sampled frames.
- Temporal sampling has two modes (`data.sampling_mode`). `cycle` (default)
  estimates the cardiac period from the frame-brightness autocorrelation and
  resamples a fixed number of cycles onto a phase grid, anchoring evaluation
  clips at end-diastole; it falls back to `window` sampling when no reliable
  cycle is detected. `window` mode jitters the clip window during training
  and can bias frames toward systolic phases with
  `data.phase_bias_strength` (0 disables it; frame mean intensity serves as
  the phase proxy). `data.temporal_stride_jitter` and
  `data.frame_dropout_prob` add further train-time temporal augmentation.
  Evaluation is always deterministic; `data.eval_phase_bias_strength`
  optionally applies the same phase weighting without jitter.
- Inputs are resized with `data.resize_mode`: `letterbox` (default) preserves
  the aspect ratio with zero padding; `stretch` reproduces the legacy
  direct resize.
- Mixed precision and gradient accumulation are enabled by default. Reduce
  `data.batch_size` if a 32-frame clip does not fit in GPU memory.
- The current scope includes training, held-out-fold validation, and
  independent external-cohort testing. Explainability and DeLong
  model-comparison testing remain deferred.
